# Icon font subsetting & missing-icon monitor

Production builds ship a **subset** of the Material Symbols Rounded variable font that contains only the icons actually used in the app. This keeps the shipped font tiny (~300 KB instead of ~5 MB) while still rendering every icon.

`scripts/icons/subset-icons.mjs` is the single tool that both **validates** the icons referenced in the source and **generates** that subset. Everything is derived directly from the full font shipped by the [`material-symbols`](https://www.npmjs.com/package/material-symbols) npm package, so there is no external codepoints map that can go stale.

## Commands

Run from `packages/app`:

```bash
npm run icons:check    # validate only (no file written) – fast, CI / pre-commit
npm run icons:subset   # validate + write the subset woff2
```

`icons:subset` writes:

```
src/assets/fonts/MaterialSymbolsRounded.woff2
```

which is the file referenced by `src/css/font.pro.scss` (loaded only in production builds). That file is **git-ignored** (see the repo root `.gitignore`); it is regenerated by CI on every build and must not be committed.

> Note: `src/apps/controlHub/css/font.pro.scss` and `src/apps/dashboard/css/font.pro.scss` are legacy/unused (no build imports them); all apps load the shared `src/css/font.pro.scss`, so only the single output above is produced.

## How it works

1. **Scan** – `src/**/*.{vue,ts,tsx,js,jsx,html}` is scanned for `sym_r_<name>` usages (the form Quasar uses for Material Symbols Rounded icons).
2. **Allowlist** – names that are built dynamically (e.g. `` :name="`sym_r_${icon}`" ``) cannot be found by scanning, so they are listed in `scripts/icons/icons.allowlist.txt` and merged into the icon set.
3. **Validate** – every icon name is shaped with HarfBuzz against the full font. A real icon collapses to exactly one non-`.notdef` glyph (its ligature); a typo or non-existent icon does not, and the script exits with a non-zero code listing the offending names and where they were found.
4. **Subset** – the icons' own codepoints plus the ligature input glyphs (`a-z`, `0-9`, `_`) are subset with `no-layout-closure`, so only the used icons are kept while their name ligatures still resolve at runtime.

## Adding / fixing icons

- **New static icon** – just use `sym_r_<name>` in code. It is picked up automatically; if the name is valid it ends up in the subset.
- **New dynamic icon** – add the bare name (without `sym_r_`) to `icons.allowlist.txt`. Anything whose `sym_r_` prefix is added at runtime is invisible to the scanner and must be allowlisted, otherwise it silently ships as a blank box. Common cases:

  - a bare name stored in data and rendered later, e.g. `icon: 'vpn_lock'` in a store consumed via `` :name="`sym_r_${icon}`" ``;
  - a bare name passed as a prop to an icon wrapper, e.g. `image-name="place_item"` (`AccountOperations`), or `name`/`icon` props on `BtIcon` / files `Action`;
  - a template literal such as `` `sym_r_${biometricIcon}` ``.

  (A bare name that _also_ appears somewhere as a literal `sym_r_<name>` is already covered and does not need an entry.)

- **`icons:check` fails** with "icon not found":
  - fix the typo, or
  - if it is a genuinely new Material Symbols icon missing from the bundled font, bump the `material-symbols` devDependency to a newer version, or
  - if it is a valid dynamic name, add it to `icons.allowlist.txt`.

Because CI runs `npm run icons:subset` (which validates first), a missing or misspelled icon **fails the build** instead of silently shipping as a blank box.
