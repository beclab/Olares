# Goose on Olares：验收测试用例

## 范围与版本基线

验证用户从 Olares Market 安装 Goose 后的完整使用流程，包括默认 AI Router 连接、Desktop 远程连接、Terminal 使用、文件操作、配置变更和数据持久化。

基线版本：Olares 1.12.7 或更高版本，Goose 应用 0.0.13，Goose 服务端及 Desktop 1.54.0。执行前记录实际版本。本文是待执行的测试用例，不是已完成的测试报告。实际结果单独记录在[2026-10-13 验收报告](results-2026-10-13.zh.md)中。

## 测试环境

| 项目 | 要求 |
|:---|:---|
| 账号 | 具有安装应用和修改 Goose 配置权限的 Olares 用户 |
| 安装来源 | Olares Market 中的 Goose 应用页面 |
| AI Router | 已安装，并配置已就绪、支持工具调用的默认聊天模型 |
| 客户端 | Goose Desktop 1.54.0；分别验证支持的 Windows、macOS 和 Linux 客户端 |
| 网络 | Desktop 主流程开启 LarePass VPN |
| 测试文件 | 仅使用 `/config/workspace/goose-demo` 及 Home、External 中专门准备的测试副本 |
| 可选服务商 | 有效的第三方账号、支持工具调用的模型 ID、服务地址和 API 密钥 |
| 架构 | 记录 amd64 或 arm64，分别报告验证结果 |

测试证据不得包含 Goose 连接密钥或模型 API 密钥。验证单请求顺序对话前，暂停其他测试会话。排查 Goose 模型错误前，先确认 Router 本身可成功完成一次对话。

## 测试数据与证据

使用中文用户指南中的 `notes.md` 和 `brief.md` 任务。必须保留的事实为：优化客户首次使用流程、缩短首次配置时间、配置检查清单、故障排查指南、日期 `2026-11-30`，以及指南负责人尚未确定。按事实是否完整评估，不要求生成文案逐字一致。

每条用例记录：用例 ID、执行人、执行时间及其时区、应用／客户端／操作系统版本、架构、模型 ID、实际结果、通过／失败／阻塞／未执行状态及脱敏证据。证据可包括相关截图、文件内容或请求记录。仅有聊天回复不能证明文件已实际写入。

P0 表示核心流程或访问边界；P1 表示辅助流程或回归验证；P2 表示可选能力。前提条件未满足应标记为阻塞，不得记为通过。

## 核心流程用例

| ID | 优先级 | 前提条件 | 操作步骤 | 预期结果 |

| GOOSE-001 | P0 | 尚未安装 Goose；Router 前提满足 | 在 Market 搜索 Goose，打开应用页面，点击获取并安装，等待完成。 | 安装完成并进入运行中状态。可从 Launchpad 打开 Goose Terminal；设置中可找到 Goose ACP，且不将其描述为浏览器聊天界面。 |
| GOOSE-002 | P0 | 全新安装；未修改服务商配置 | 查看应用环境变量，在 Goose Terminal 启动 `goose session`，发送简短问候。 | `GOOSE_PROVIDER=custom_olares_router`、`GOOSE_MODEL=default-chat`。无需填写默认连接的模型 API 密钥即可获得完整回复；Router 证据确认使用其默认模型。 |
| GOOSE-003 | P0 | Desktop 已安装；VPN 已开启；Goose 运行中 | 从设置复制 ACP HTTPS 地址，从 Terminal 获取连接密钥；配置外部服务端、地址、密钥和 `/config/workspace`，新建对话发送就绪确认消息。 | 客户端成功连接并收到完整回复。当前会话使用远程服务，无需为既有 Router 配置重新执行服务商首次配置。 |
| GOOSE-004 | P0 | Desktop 已成功连接 | 将客户端密钥替换为错误值，应用配置并建立新连接；再恢复正确值重新连接。 | 错误密钥被拒绝，不能进行远程对话或文件操作；恢复正确密钥后可正常使用。 |
| GOOSE-005 | P0 | Desktop 已连接；模型支持工具调用；示例文件不存在或已隔离 | 执行指南中的项目简报提示词，批准文件操作；在 Terminal 中用 `ls` 和 `cat` 检查两份文件。 | 两份文件均在指定目录中实际存在。简报保留所有事实，没有编造负责人或时间安排。指定示例目录外无写入。 |
| GOOSE-006 | P1 | GOOSE-005 通过 | 发送追加“后续行动”的请求，再次读取文件。 | 磁盘文件实际更新，原事实保留，建议明确标注为提议。 |
| GOOSE-007 | P0 | Goose 运行中；Desktop 无进行中的请求 | 打开 Terminal，执行 `cd /config/workspace` 和 `goose session`，先发送问候，再请求读取简报，最后按 Ctrl+C 退出。 | 两次请求均使用默认服务商完成，正确读取文件；退出 CLI 不停止服务，Desktop 仍可连接。 |
| GOOSE-008 | P1 | 简报存在；模型无进行中的请求 | 执行指南中的一次性 `goose run -t` 命令，比较执行前后的文件。 | 正确概括待确认事项，命令成功结束，文件未修改。 |
| GOOSE-009 | P1 | 至少一个已完成的 Terminal 会话 | 执行 `goose session list`，选择实际 ID，运行 `goose session --resume --session-id ID`，询问先前对话内容。 | 恢复指定会话及其历史，不创建无关的空白会话。 |

## 验收标准

- 发布基线上的所有适用 P0、P1 用例通过。第三方服务商或平台条件不足时，记录为阻塞或未执行，不推断覆盖结果。
- 明确报告操作系统及架构覆盖。amd64 通过不代表 arm64 已验证；一个 Desktop 操作系统通过不代表三个平台均已验证。
- 不存在未解决的严重数据丢失、错误授权或核心连接缺陷；总结和生成内容保留输入事实。
- 配置测试后恢复 AI Router、关闭 Home／External 访问、关闭自动标题，恢复原用户时区；只保留指定测试文件，移除不再使用的服务商密钥。
