# 验证 Pterodactyl 游戏服务器部署

从 Market 安装 Pterodactyl Panel、修改游戏模板或准备开放服务器后，可以使用本清单进行验收。清单为管理员定义可重复的操作和通过标准，并区分已有运行证据与仍需执行的检查。

## 范围与执行规则

清单覆盖 Panel 管理、本地 Wings 节点、作为主示例的 Terraria/TShock 服务器，以及独立的可选 Minecraft Java 服务器。应用状态正常、API 请求已接受或 TCP 端口可达，都不能单独作为游戏运行或恢复通过的依据。

恢复和权限测试应使用可删除的服务器。每个用例都应记录应用版本、游戏版本、模板、时间、预期结果、实际结果和证据。不要在结果中附加密码、访问令牌、会话 Cookie 或完整的 Wings 配置。

| 优先级 | 含义 |
| --- | --- |
| P0 | 涉及访问控制、游戏启动或数据恢复；失败时不能依赖相关流程 |
| P1 | 核心管理操作；日常使用前应排查失败原因 |
| P2 | 针对具体环境的兼容性或容量验证 |

表格中的“已有证据”表示此前运行验证观察到了等价行为；“待执行”表示尚未完成所述场景的端到端验证。历史证据不能替代对当前安装版本的重新验收。
