# 自定义路由 ID 导致应用无法访问

如果设置自定义路由 ID 后，一个或多个 Olares 应用 URL 无法访问，请参考本文排查。在受影响的 Olares 版本中，重复的路由 ID 可能导致网关拒绝冲突的路由配置。

## 现象

- 问题出现在新增或修改自定义路由 ID 后，或者 Olares 使用该配置重启后。
- 某个应用 URL 返回 `404`，或多个互不相关的应用 URL 同时失效。
- 同一个 Olares 账号下，有两个应用入口使用了相同的自定义路由 ID。

## 原因

自定义路由 ID 会成为用户 Olares 域名中的子域名，因此在使用该域名的应用入口之间必须保持唯一。如果受影响的版本接受了重复值，生成的网关配置中就可能出现重复主机名。网关无法加载这份路由配置时，受影响的范围可能不止两个发生冲突的应用。

## 在设置中移除冲突

如果你仍能通过其他可用的 Olares URL 打开设置：

1. 确认问题发生前刚刚修改过的自定义路由 ID。
2. 打开**设置** > **应用**，选择使用重复路由 ID 的其中一个应用。
3. 在**入口**下，打开受影响的入口。
4. 在**端点配置**下，移除自定义路由 ID，或将其替换为唯一值。
5. 提交更改，然后重新打开原来的应用 URL。

创建新的路由 ID 时，请勿复用其他应用的默认路由或自定义路由 ID。路由 ID 在比较时不区分英文字母大小写。

## 设置也无法访问

请勿执行从其他用户支持案例中复制的 Kubernetes patch 命令。Application 资源名称包含账号和安装环境特有的信息，修改错误的资源可能影响应用数据或其他用户。

请先记录以下信息：

- Olares 版本。
- 修改路由 ID 的应用和入口。
- 自定义路由 ID；如有需要，请移除其中的个人域名信息。
- 只有一个应用受影响，还是所有 Olares URL 都无法访问。
- 完整的 HTTP 状态或浏览器错误，以及问题开始的时间。

请通过私密渠道联系 Olares 支持，由支持人员针对你的安装环境移除冲突配置。如果支持人员要求提供日志，请参考[收集诊断信息](../collect-diagnostic-information.md)。

常规路由 ID 配置方法详见[自定义应用 URL](../olares/settings/custom-app-domain.md)。
