# Upgrade to Olares 1.12.6

Olares 1.12.6 introduces several architecture and workflow changes.

This guide explains which existing apps and workflows changed in 1.12.6, whether you need to take action, and where to find the detailed steps.

:::warning Before changing an app
Open the app-specific migration guide and back up or export the data it identifies. When uninstalling an old app, do not select **Also remove all local data** unless the guide tells you to. This option can permanently delete models, workflows, settings, or other app data.
:::

## Migrate legacy shared apps

Before Olares 1.12.6, a shared app used a server component and separate client-side access points. The new architecture provides one shared service that an administrator manages centrally. Members with access can open an app with a built-in interface directly from Launchpad without installing a separate client.

Legacy v2 shared apps continue to start, stop, and run after the system upgrade, but you cannot upgrade them directly to the new architecture. To identify a legacy app, open its details page in Market and check **Information** > **Compatibility**:

- A legacy v2 app typically shows `Olares >=1.12.3-0, <1.12.6`.
- A new shared app shows `Olares >=1.12.6-0`.

Choose the migration path for your app:

- **ComfyUI**: Uninstall **ComfyUI Shared** without removing local data, then install the new ComfyUI app. After installation, check that your models, plugins, workflows, and input/output files are available. See [ComfyUI migration notes](/use-cases/comfyui-common-issues#how-to-migrate-to-the-new-comfyui-after-upgrading-to-olares-1126).
- **Dify**: Export each app as a DSL file and download the original knowledge base documents. Logs, conversations, processed chunks, and existing vector indexes are not preserved. See [Migrate Dify to the new architecture](/use-cases/dify-upgrade).
- **OnlyOffice**: Back up the data identified in the migration guide, install the compatible 1.12.6 version, and restore the data. See [Migrate OnlyOffice to the new architecture](/use-cases/onlyoffice-migration).
- **SearXNG**: Copy the preferences hash from **Preferences** > **Cookies**, install the new app, and restore the hash. See [Migrate SearXNG to the new architecture](/use-cases/searxng).
- **Xinference**: Reinstall the app and download your models again. Existing models cannot be migrated automatically because the new version uses the Common directory and a revised storage layout. See [Migrate Xinference to the new architecture](/use-cases/xinference).
- **Apps without user-created data**: For apps such as Falco and MTranServer, uninstall the v2 app and install the new version from Market.

For the architecture overview and complete migration options, see [Shared applications](/manual/olares/market/shared-apps).

## Move from standalone Ollama to Engine Base

Starting with Olares 1.12.6, the standalone Ollama app is no longer available for new installations. An existing installation continues to run, and you can still use its CLI and API endpoint, but the app will not receive further updates.

For a supported deployment, install **Ollama Engine Base** from Market and create a model instance in Model Console. Each instance provides a dedicated Base URL, accelerator status, and performance measurements.

1. Install **Ollama Engine Base** from Market.
2. Create an instance for the model you used with standalone Ollama.
3. Wait for the model to download and check that the instance is running.
4. Copy the Base URL from Model Console.
5. Replace the old Ollama endpoint in Open WebUI, LobeChat, agents, or other client apps.
6. Test the new connection before removing the standalone Ollama app.

For engine selection, model sources, accelerator settings, and client connections, see [Run local AI models with Engine Base apps](/use-cases/llm-base-apps).

## Replace Studio with the new app development workflow

Studio is no longer available in Market. Packaging and porting apps now use Olares CLI and the `olares-chart` Agent Skill.

To continue developing Olares apps:

1. Install Olares CLI and its Agent Skills, or use an Olares agent app that includes them.
2. Use the chart workflow to create, inspect, and test the app package.
3. Follow the current submission guide to validate the chart and open a draft pull request against `beclab/apps:main`.

See [Install and use Agent Skills](/developer/cli-agent-skills) and [Submit applications](/developer/develop/submit-apps).

## Review other upgrade notes

### AI apps

Olares 1.12.6 changes how AI apps use resources and accelerators. If an AI app installed before the upgrade does not start correctly, uninstall the old version and install the latest compatible version from Market. If you already did this while using the 1.12.6 release candidate, no further action is required.

Before uninstalling an app with user-created data, follow its migration guide. Do not remove local data unless you have a verified backup or the guide says the data is disposable.

### Sonarr, Radarr, and other *Arr apps

In Olares 1.12.6, *Arr apps communicate through internal entrance URLs instead of provider URLs. Existing integrations may stop working until you update their connection settings.

1. Update each *Arr app and download client to the latest version available for Olares 1.12.6.
2. For each app, open **Settings** > **Applications** > **[App name]** > **Entrances**.
3. Set **Authentication level** to **Internal**, then copy the HTTPS endpoint.
4. Replace the old URLs in Prowlarr, Sonarr, Radarr, download clients, and related integrations.
5. Use each app's **Test** function. Save the settings after the connection succeeds.

See [Upgrade notes for *Arrs](/use-cases/arrs-upgrade).

### Olares One automatic startup

Olares One can now power itself back on after a power outage. The **Automatic startup** toggle is under **Settings** > **My Olares** > **My Hardware**, but it requires a supported EC firmware version.

:::warning Before updating firmware
Follow the official instructions exactly, keep the device connected to stable power, and do not interrupt the update. An interrupted firmware update can prevent the device from starting correctly.
:::

Update the EC firmware, confirm the reported version in BIOS, then enable **Automatic startup**. See [Manage BIOS and EC](/one/update-firmware).

## Check your system after upgrading

1. Refresh the Olares desktop manually.
2. Open the apps you use most and check that they start normally.
3. Test shared-app entrances and API connections from each dependent client.
4. Confirm that migrated data, models, workflows, and settings are present.
5. Remove legacy data only after the new app and its integrations work as expected.

For an overview of the release, see the [Olares 1.12.6 blog post](https://www.olares.com/blog/olares-1-12-6/). For new and updated documentation, see [What's new in docs](/manual/release-notes).
