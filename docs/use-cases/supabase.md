# Connect your apps to a Supabase backend on Olares

Supabase combines a PostgreSQL database with authentication, file storage, realtime updates, and Edge Functions. Studio provides a browser interface for managing your data and services.

On Olares, these services run on your own device. Your automation workflows, reports, document search, and custom applications can share a backend without keeping a separate copy of the data in each service. AI requests follow the models you select in Router. Choose local models to keep that processing on your device too.

The examples use fictional home renovation projects. n8n records a delivery task, Metabase summarizes costs, Flowise answers questions about project notes, and Code Server connects a small application with user-level access controls. You can follow each connection independently.

## Learning objectives

- Choose the correct Supabase address and credential for each app.
- Record tasks with n8n and analyze costs with Metabase.
- Build document retrieval in Flowise with models from Router.
- Connect a JavaScript application using ordinary user credentials and row-level security.

## Install Supabase

1. Open Market and search for "Supabase".
2. Click **Get**, then **Install**, and wait for installation to complete.
3. Open Supabase from Launchpad. Studio opens the local project.

This package runs one self-hosted project. You do not need a Supabase Cloud account. Install the consumer apps you want to use from Market. For n8n's initial account setup, see [Automate workflows with n8n](n8n.md#set-up-n8n).

:::info Database access
Package 0.0.13 declares TCP port mappings for database clients. These ports provide LAN/VPN access and still require a database password. They are broader than an allowlist for two specific apps. API clients such as n8n and Flowise use HTTPS instead.
:::

## Collect connection details

### Copy addresses from Olares

Open **Settings > Applications > Supabase**. Use the address for the service you need:

| Value | Where to find it | Used by |
| --- | --- | --- |
| API URL | The **Supabase API** entrance | n8n, Flowise, Supabase SDK |
| Database host | Supabase's application domain, without `https://` or a path | Metabase |
| Database port | The app's **Ports** entries | Metabase |
| Studio URL | The **Supabase Studio** entrance | Your browser |

Copy the API URL as a complete HTTPS URL. Do not append `/rest/v1` in the Supabase credential fields. Studio's address and the API address can differ.

To distinguish the application domain from its web entrances, run `olares-cli settings apps get supabase` in a terminal with a signed-in Olares CLI profile. Use the top-level **URL** as the database host and **Ports** for the mappings. See [Install olares-cli](https://www.olares.com/docs/developer/cli-install) for CLI setup.

The package maps the session pool to `45432` and the transaction pool to `46543`. Use the actual ports shown for your installation. For Metabase, start with the session pool. A LAN IP can also be used as the database host when it is reachable from the consumer app. See [Olares port mappings](https://www.olares.com/docs/developer/develop/package/manifest#ports) for the network scope.

### Copy the appropriate credential

In Studio, open **Project Settings > API Keys > Legacy anon, service_role API keys**.

| Credential | Purpose |
| --- | --- |
| `anon` | Client applications that sign users in and follow RLS policies |
| `service_role` | Trusted backend integrations such as n8n and Flowise. It bypasses RLS |
| Database password | PostgreSQL connections in Metabase. An API key cannot replace it |

Use **Copy** for `anon`. For `service_role`, click **Reveal** and copy the value into the consumer app's credential store. Keep it out of browser code, source control, and screenshots. This package uses the legacy keys, rather than `sb_publishable_...` or `sb_secret_...` keys.

For the database password, open Control Hub and go to **Browse > supabase-&lt;your-username&gt; > Secrets > supabase-secrets**. Under **Data**, reveal the decoded `POSTGRES_PASSWORD` value. See [View Secrets](https://www.olares.com/docs/manual/olares/controlhub/manage-resource#view-secrets). Viewing the existing password does not require editing the Secret.

## Prepare project data

In Studio, open **SQL Editor**, create a query, and run:

```sql
create table public.project_tasks (
  id bigint generated by default as identity primary key,
  project text not null,
  title text not null,
  status text not null default 'todo'
);
alter table public.project_tasks enable row level security;

create table public.project_costs (
  id integer primary key,
  project text not null,
  amount integer not null
);
alter table public.project_costs enable row level security;

insert into public.project_costs values
  (1, 'Lakeview', 100),
  (2, 'Riverside', 200),
  (3, 'Maple', 300);
```

The amounts are fictional USD examples. Open **Table Editor** to inspect the tables. RLS is enabled, so anonymous clients cannot read these records without an appropriate policy. The following n8n integration uses a trusted service credential.

## Connect other apps

### Record a delivery task with n8n

1. Open n8n and create a workflow with a manual trigger.
2. Add a **Supabase** node and create a Supabase credential.
3. Set **Host** to the Supabase API URL. Paste the legacy `service_role` key into the credential's **Service Role Secret** field. Save the credential. Newer node versions may label this field **Secret Key**.
4. Select the row creation operation and table `project_tasks`.
5. Add the following field values:

   | Field | Value |
   | --- | --- |
   | `project` | `Lakeview` |
   | `title` | `Confirm cabinet delivery for 10 November 2026` |
   | `status` | `todo` |

6. Execute the node. Open `project_tasks` in Studio's **Table Editor** to find the new task.
7. To update the task, add another Supabase node, choose the update operation, filter by the returned `id`, and set `status` to `done`.

Replace the manual trigger with a form, webhook, or schedule as your workflow grows. Keep the Supabase credential on the n8n server. The same row operations can collect client requests, delivery updates, or other structured records.

### Summarize project costs with Metabase

Open Metabase and use **Admin settings > Databases > Add a database**. Choose PostgreSQL and enter:

| Field | Value |
| --- | --- |
| Display name | `Home project costs` |
| Host | Supabase's application domain, without a scheme |
| Port | `45432`, or the session port listed in Olares |
| Database name | `postgres` |
| Username | `postgres.supabase` |
| Password | The decoded `POSTGRES_PASSWORD` |
| SSL | Off for this package's LAN connection |

Save the connection. Create a SQL question against this database:

```sql
select project, amount
from public.project_costs
order by id;
```

To calculate the total, run:

```sql
select count(*) as records, sum(amount) as total_usd
from public.project_costs;
```

The sample data returns three rows and USD 600. Save the question and add it to a dashboard to track your own project costs. The transaction pool on `46543` also supports these queries. Use `postgres.supabase` for either pool because the username includes the pool's tenant name.

:::warning Database privileges and network scope
This example uses the installation administrator's database login in a Metabase instance you control. Before sharing reporting access, configure a dedicated read-only database account and appropriate Metabase permissions. TCP mappings allow LAN/VPN connections, rather than only the Metabase app. Do not substitute an API key or use a browser HTTPS entrance as the database connection.
:::

### Ask Flowise about project notes

Use Supabase as Flowise's vector store. Flowise keeps its own application database configuration. It does not need a direct PostgreSQL connection to Supabase for this workflow.

#### Prepare Flowise and Router

In Router, select the chat and embedding defaults. Use `default-chat` and `default-embedding` in this example. Copy the OpenAI-compatible **Base URL** for **Apps in Olares** from Router's connection example, including `/v1`. For other connection locations and key requirements, see [Connect AI apps](https://www.olares.com/docs/manual/best-practices/connect-ai-apps).

The embedding example uses Jina CLIP v2 with 1024 dimensions. Keep the same embedding model for document ingestion and retrieval. A different dimension requires a different vector column and a fresh index.

:::details Add Router defaults to Flowise's model dropdowns
The OpenAI nodes in this Flowise version use a model dropdown. Add the Router routes to a local catalog before building the flow.

1. Open the Flowise container's **Terminal** in Control Hub and run:

   ```bash
   node <<'NODE'
   const fs = require('fs');
   const base = '/usr/local/lib/node_modules/flowise/node_modules/flowise-components';
   const source = [base + '/models.json', base + '/dist/models.json']
     .find(path => fs.existsSync(path));
   if (!source) throw new Error('Bundled model catalog not found');
   const catalog = JSON.parse(fs.readFileSync(source, 'utf8'));
   for (const [category, provider, name] of [
     ['chat', 'chatOpenAI', 'default-chat'],
     ['embedding', 'openAIEmbeddings', 'default-embedding']
   ]) {
     const entry = catalog[category].find(item => item.name === provider);
     if (!entry) throw new Error('Model provider not found: ' + provider);
     if (!entry.models.some(model => model.name === name)) {
       entry.models.push({ label: name, name });
     }
   }
   fs.writeFileSync('/home/node/.flowise/olares-models.json', JSON.stringify(catalog, null, 2));
   NODE
   ```

2. In **ConfigMaps > flowise-config**, add this entry under `data`, then restart Flowise:

   ```yaml
   MODEL_LIST_CONFIG_JSON: "/home/node/.flowise/olares-models.json"
   ```

This keeps the bundled model options and adds the two routes. If you already maintain a custom catalog, add the routes to that file instead. As with the compatibility setting below, a direct ConfigMap edit can be replaced during an app upgrade.
:::

:::details WebSocket compatibility for Flowise image 3.1.4
This image reports Flowise 3.1.2 and uses Node.js 20. Its Supabase dependency can fail with `Node.js 20 detected without native WebSocket support`. Apply this workaround to that version before continuing:

1. On your computer, create `supabase-websocket.cjs` containing:

   ```js
   globalThis.WebSocket ||= require('/usr/local/lib/node_modules/flowise/node_modules/ws');
   ```

2. Upload it with Files to `Data/flowise/`. The file is mounted in Flowise at `/home/node/.flowise/supabase-websocket.cjs`.
3. In Control Hub, open the Flowise namespace, select **ConfigMaps > flowise-config**, and add the following entry under `data`:

   ```yaml
   NODE_OPTIONS: "--require=/home/node/.flowise/supabase-websocket.cjs"
   ```

   Append the option if `NODE_OPTIONS` already has a value.
4. Restart the Flowise workload. See [Configure variables in Control Hub](https://www.olares.com/docs/manual/olares/settings/manage-app-env#configure-variables-in-control-hub).

Direct Control Hub edits can be replaced during an app upgrade. Keep the file and reapply the setting, or use an app package that includes the compatibility fix.
:::

#### Create a document store

Run this query in Supabase's **SQL Editor**:

```sql
create extension if not exists vector with schema extensions;
create table public.project_documents (
  id uuid default gen_random_uuid() primary key,
  content text,
  metadata jsonb default '{}',
  embedding extensions.vector(1024)
);
alter table public.project_documents enable row level security;

create function public.match_project_documents(
  query_embedding extensions.vector,
  match_count integer default 4,
  filter jsonb default '{}'
) returns table(id uuid, content text, metadata jsonb, similarity float)
language sql stable security invoker
set search_path = public, extensions
as $$
  select id, content, metadata,
         1 - (embedding operator(extensions.<=>) query_embedding)
  from public.project_documents
  where metadata @> filter
  order by embedding operator(extensions.<=>) query_embedding
  limit match_count
$$;
```

#### Build the chatflow

In Flowise, create a chatflow with these nodes:

| Node | Configuration |
| --- | --- |
| Plain Text | A project note in **Text**. Set **Additional Metadata** to `{"project":"Lakeview"}` |
| OpenAI Embeddings | **Model Name** `default-embedding`, Router **Base Path**, **Batch Size** `1`, **Encoding Format** `float` |
| Supabase | API URL in **Supabase Project URL**, a credential containing `service_role`, **Table Name** `project_documents`, **Query Name** `match_project_documents` |
| ChatOpenAI | **Model Name** `default-chat`, Router **Base Path** |
| Retrieval QA Chain | Connect the chat model and the Supabase retriever |

For model credential fields, apps inside Olares do not need a Router API key. Use `olares` as a placeholder when the field requires a value.

Connect Plain Text's **Document** and OpenAI Embeddings to Supabase. Connect **Supabase Retriever** and ChatOpenAI to Retrieval QA Chain. Save the flow and run the vector upsert action before asking a question.

For the first note, use:

```text
Lakeview cabinet delivery is on 10 November 2026.
Confirmation reference: LAKEVIEW-6728.
```

Ask “What is the Lakeview cabinet delivery date and confirmation reference?” Compare the answer with the source note. Add another Plain Text node for Riverside with its own note and `{"project":"Riverside"}` metadata. Set **Supabase Metadata Filter** to that JSON object when you want retrieval limited to Riverside.

The single-item embedding batch is required by the Jina CLIP v2 service used here. Change batch size only when the selected embedding service supports it.

### Build a small application in Code Server

Use a Node.js project in Code Server. The SDK example requires Node.js 22 or later and npm. Code Server's editor does not guarantee that npm is installed. Prepare the project runtime first using the [Node.js installation guide](https://nodejs.org/en/download).

In Studio, run:

```sql
create table public.user_notes (
  id uuid default gen_random_uuid() primary key,
  owner_id uuid not null,
  note text not null
);
alter table public.user_notes enable row level security;
grant select, insert, update, delete on public.user_notes to authenticated;
create policy own_notes on public.user_notes
for all to authenticated
using (auth.uid() = owner_id)
with check (auth.uid() = owner_id);
```

Open **Authentication > Users > Add user > Create new user**. Enter an email and password, keep **Auto confirm user?** enabled for this local example, and create the user. This creates a confirmed application account without sending a confirmation email.

In your Code Server project terminal, install the SDK:

```bash
npm install @supabase/supabase-js@2.118.0
```

Create `.env` with values from your own installation and the user you created:

```dotenv
SUPABASE_URL=https://YOUR_SUPABASE_API_HOST
SUPABASE_ANON_KEY=YOUR_LEGACY_ANON_KEY
SUPABASE_USER_EMAIL=YOUR_USER_EMAIL
SUPABASE_USER_PASSWORD=YOUR_USER_PASSWORD
```

Add `.env` to `.gitignore`. Create `notes.mjs`:

```js
import { createClient } from '@supabase/supabase-js';

const client = createClient(
  process.env.SUPABASE_URL,
  process.env.SUPABASE_ANON_KEY,
  {
    auth: { persistSession: false },
    realtime: { transport: WebSocket }
  }
);

const { data: session, error: loginError } =
  await client.auth.signInWithPassword({
    email: process.env.SUPABASE_USER_EMAIL,
    password: process.env.SUPABASE_USER_PASSWORD
  });
if (loginError) throw loginError;

const { error: insertError } = await client.from('user_notes').insert({
  owner_id: session.user.id,
  note: 'Ask the Lakeview contractor to confirm the delivery window.'
});
if (insertError) throw insertError;

const { data: notes, error: readError } =
  await client.from('user_notes').select('id, note');
if (readError) throw readError;
console.table(notes);

const { data: greeting, error: functionError } =
  await client.functions.invoke('hello', { body: { name: 'Lakeview' } });
if (functionError) throw functionError;
console.log(greeting);
await client.auth.signOut();
```

Run `node --env-file=.env notes.mjs`. The terminal displays the user's notes and the response from the included `hello` Edge Function. A different signed-in user cannot read these notes under the policy above. Do not replace the `anon` key with `service_role` to bypass a policy error.

## Extend your application

Use **Storage** in Studio to create a private bucket for receipts or project files. Define storage policies for the intended users before accessing it with the SDK. Uploading, downloading, and short-lived signed URLs use the same API address. See [Storage access control](https://supabase.com/docs/guides/storage/security/access-control).

For live updates, add the intended table to the `supabase_realtime` publication and subscribe with the SDK. Keep RLS policies in place. Wait for the database subscription to be ready before relying on the first event, especially just after adding a table. See [Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes).

Authentication, storage, realtime updates, and functions let your application grow beyond a shared database. External sign-in providers and email delivery need their own configuration. A local, auto-confirmed user does not configure those services.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| n8n or Flowise cannot authenticate | Use the **Supabase API** URL and the legacy `service_role` key |
| Metabase cannot connect | Check the app's mapped ports, reachable host, database password, and the `postgres.supabase` username |
| Metabase connects but cannot see data | Check the selected schema and the database account's permissions |
| Flowise reports missing WebSocket support | Apply the version-specific compatibility step above |
| Flowise embeddings return a single-text error | Set embedding **Batch Size** to `1` |
| An SDK query returns no rows | Check the signed-in user and RLS policy before changing credentials |

For backup planning, include both PostgreSQL data and uploaded storage objects. A Studio session or a successful application query is not a database backup.
