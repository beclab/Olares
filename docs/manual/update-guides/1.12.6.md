# What to do after updating to Olares 1.12.6

Olares 1.12.6 introduces several architecture and workflow changes.

This guide explains which existing apps and workflows changed in 1.12.6, whether you need to take action, and where to find the detailed steps.

:::warning Before app migration
Open the app-specific migration guide and back up or export the data it identifies. When uninstalling an old app, carefully consider whether to select **Also remove all local data**. This option can permanently delete models, workflows, settings, or other app data.
:::

## Find what applies to you

| If this applies to you | What to do |
| --- | --- |
| You installed a shared app before Olares 1.12.6 | Check whether it uses the older architecture. If it does, follow its migration guide before uninstalling it. [View migration options](#shared-apps-installed-before-olares-1126). |
| An AI app installed before 1.12.6 does not start after the update | Back up the app data, then install the latest compatible version from Market. [Learn more](#ai-apps-that-fail-to-start). |
| You use standalone Ollama | No immediate action is needed. Use Ollama Engine Base when deploying new models. [See how](#move-from-standalone-ollama-to-engine-base). |
| You use Sonarr, Radarr, Prowlarr, or a separate download client | Update any connection URLs and paths affected by Olares 1.12.6. [See what changed](#arr-apps-and-download-clients). |
| You previously used Studio | Use the current Agent Skills and app submission guides. [View the replacement docs](#replace-studio-with-the-new-app-development-workflow). |

## Shared apps installed before Olares 1.12.6

Before Olares 1.12.6, shared apps used a server-and-client architecture. This documentation refers to apps that use this older architecture as v2 shared apps. Existing v2 shared apps continue to work after the update, but cannot be upgraded in place. Starting with Olares 1.12.6, each shared app runs as a single service managed by the administrator. For details, see [Shared applications](/manual/olares/market/shared-apps#explore-the-architecture-shift).

To identify a v2 app, open its Market details page and check **Information** > **Compatibility**. A v2 app typically shows `Olares >=1.12.3-0, <1.12.6`; the new version shows `Olares >=1.12.6-0`.

**Choose a migration path**

- **Preserve local data**: For ComfyUI, uninstall the old app without removing local data, then install the new version. Follow the [ComfyUI migration notes](/use-cases/comfyui-common-issues#how-to-migrate-to-the-new-comfyui-after-upgrading-to-olares-1126).
- **Follow an app-specific migration**: Use the dedicated guide for [Dify](/use-cases/dify-upgrade), [OnlyOffice](/use-cases/onlyoffice-migration), [SearXNG](/use-cases/searxng), or [Xinference](/use-cases/xinference). The data that can be preserved differs by app.
- **Reinstall directly**: Use this path only for an app that has no user-created data to migrate. Check [Shared applications](/manual/olares/market/shared-apps#option-2-perform-a-clean-reinstallation) for the current guidance.

## Move from standalone Ollama to Engine Base

Starting with Olares 1.12.6, the standalone Ollama app is no longer available in Market. Existing installations keep working, but you cannot update the app from Market.

For new deployments, use **Ollama Engine Base**:

1. Deploy the model on Ollama Engine Base.
2. Copy its Base URL from Model Console.
3. Reconfigure the clients that used the standalone Ollama endpoint.

See [Run local AI models with Engine Base apps](/use-cases/llm-base-apps) for the complete setup.

## Replace Studio with the new app development workflow

Studio is no longer available in Market, and its documentation has been retired.

Use these guides for the replacement workflow:

- [Install and use Agent Skills](/developer/cli-agent-skills) for the Olares CLI skill bundles, including `olares-chart`.
- [Submit applications](/developer/develop/submit-apps) for the current Market submission process.

## Other changes that might affect you

### AI apps that fail to start

Some AI apps installed before 1.12.6 might not start after the upgrade. If an app is affected, uninstall it and install the latest compatible version from Market. No further action is needed if you already reinstalled it during the 1.12.6 release candidate.

Before uninstalling an app with user-created data, follow its migration guide and preserve the data it identifies.

### *Arr apps and download clients

Olares 1.12.6 changes two parts of the *Arr setup:

- **Connections**: *Arr apps now communicate through internal entrance URLs instead of provider URLs.
- **Paths**: *Arr apps and download clients now use a unified mount structure.

Update the affected URLs and paths by following [Upgrade notes for *Arrs](/use-cases/arrs-upgrade). If you use a separate download client, also check [Upgrade notes for download clients](/use-cases/download-clients-upgrade).

## Optional: Enable automatic startup on Olares One

The **Automatic startup** toggle is available under **Settings** > **My Olares** > **My Hardware**. It starts Olares One automatically when power is connected or restored.

The feature requires Olares OS 1.12.6 or later and EC firmware 1.03 or later. If the requirement is not met, the toggle remains disabled. See [Manage BIOS and EC](/one/update-firmware) to check or update the EC firmware.
