# 用 Supabase 为 Olares 应用提供统一后端

Supabase 将 PostgreSQL 数据库、用户认证、文件存储、实时更新和 Edge Functions 集成在一起。你可以通过浏览器中的 Studio 管理数据和服务。

在 Olares 上，这些服务运行在自己的设备中。自动化工作流、报表、资料问答和自己开发的应用可以共用一套后端，减少在不同服务中重复保存数据。AI 请求使用 Router 中选择的模型。选择本地模型，也可以让这部分处理留在设备内。

本文以几个虚构的家庭装修项目为例：用 n8n 记录交付任务，用 Metabase 汇总费用，用 Flowise 查询项目资料，再通过 Code Server 开发一个按用户隔离数据的小应用。你也可以单独使用其中任意一种连接。

## 学习目标

- 为不同应用选择正确的 Supabase 地址和凭据。
- 用 n8n 录入任务，用 Metabase 分析费用。
- 通过 Flowise 和 Router 为项目资料建立问答流程。
- 使用普通用户账号和行级安全策略连接 JavaScript 应用。

## 安装 Supabase

1. 打开 Market，搜索“Supabase”。
2. 点击 **Get**，再点击 **Install**，等待安装完成。
3. 从 Launchpad 打开 Supabase，进入本地项目的 Studio。

此应用包运行一个自托管项目，不需要 Supabase Cloud 账号。按需从 Market 安装要连接的应用。n8n 的首次账号设置可参考[使用 n8n 自动化工作流](n8n.md)。

:::info 数据库访问范围
0.0.13 应用包声明了供数据库客户端使用的 TCP 映射端口。这些端口提供局域网或 VPN 访问，连接时仍需数据库密码。其范围比“仅允许两个指定应用访问”更广。n8n、Flowise 等 API 客户端则使用 HTTPS。
:::

## 准备连接信息

### 从 Olares 复制地址

打开 **Settings > Applications > Supabase**，根据连接用途选择地址。

| 信息 | 获取位置 | 使用方 |
| --- | --- | --- |
| API URL | **Supabase API** 入口 | n8n、Flowise、Supabase SDK |
| 数据库主机 | Supabase 的应用域名，去掉 `https://` 和路径 | Metabase |
| 数据库端口 | 应用的 **Ports** 列表 | Metabase |
| Studio URL | **Supabase Studio** 入口 | 浏览器 |

API URL 应保留完整的 HTTPS 地址。填写 Supabase 凭据时，不要自行追加 `/rest/v1`。Studio 地址和 API 地址可能不同。

需要区分应用域名和网页入口时，可以在已登录 Olares CLI 的终端中运行 `olares-cli settings apps get supabase`。数据库主机使用输出中最上层的 **URL**，端口映射查看 **Ports**。CLI 的准备方法见[安装 olares-cli](https://www.olares.com/docs/developer/cli-install)。

此包将会话连接池映射到 `45432`，将事务连接池映射到 `46543`。以你安装实例中显示的端口为准。Metabase 优先使用会话连接池。应用能访问设备的局域网 IP 时，也可以用该 IP 作为数据库主机。网络访问范围见 [Olares 端口映射](https://www.olares.com/docs/zh/developer/develop/package/manifest#ports)。

### 获取对应凭据

在 Studio 中打开 **Project Settings > API Keys > Legacy anon, service_role API keys**。

| 凭据 | 用途 |
| --- | --- |
| `anon` | 供客户端应用登录用户，并按 RLS 策略访问数据 |
| `service_role` | 供 n8n、Flowise 等可信服务端集成使用，可以绕过 RLS |
| 数据库密码 | 供 Metabase 连接 PostgreSQL，不能用 API key 替代 |

使用 **Copy** 复制 `anon`。需要 `service_role` 时，点击 **Reveal**，将其填入连接方应用的凭据管理中。不要将它放进浏览器代码、代码仓库或截图。此包使用 legacy 密钥，不使用 `sb_publishable_...` 或 `sb_secret_...` 格式的密钥。

获取数据库密码时，打开 Control Hub，进入 **Browse > supabase-&lt;你的用户名&gt; > Secrets > supabase-secrets**，在 **Data** 中显示解码后的 `POSTGRES_PASSWORD`。操作方法见[查看 Secrets](https://www.olares.com/docs/zh/manual/olares/controlhub/manage-resource)。只需查看现有值，不需要编辑 Secret。

## 准备项目数据

在 Studio 中打开 **SQL Editor**，新建查询并运行：

```sql
create table public.project_tasks (
  id bigint generated by default as identity primary key,
  project text not null,
  title text not null,
  status text not null default 'todo'
);
alter table public.project_tasks enable row level security;

create table public.project_costs (
  id integer primary key,
  project text not null,
  amount integer not null
);
alter table public.project_costs enable row level security;

insert into public.project_costs values
  (1, 'Lakeview', 100),
  (2, 'Riverside', 200),
  (3, 'Maple', 300);
```

这里的金额是虚构的美元示例。打开 **Table Editor** 可以查看这两张表。它们已启用 RLS，匿名客户端需要适当的策略才能读取。接下来的 n8n 场景使用可信服务端凭据。

## 连接其他应用

### 用 n8n 记录交付任务

1. 打开 n8n，新建工作流，添加手动触发器。
2. 添加 **Supabase** 节点，新建 Supabase 凭据。
3. 将 Supabase API URL 填入 **Host**，将 legacy `service_role` 密钥填入 **Service Role Secret**，保存凭据。较新节点版本可能将密钥字段命名为 **Secret Key**。
4. 选择创建记录的操作，表名设为 `project_tasks`。
5. 填写以下字段：

   | 字段 | 值 |
   | --- | --- |
   | `project` | `Lakeview` |
   | `title` | `Confirm cabinet delivery for 10 November 2026` |
   | `status` | `todo` |

6. 执行节点，在 Studio 的 **Table Editor** 中打开 `project_tasks`，即可看到新增任务。
7. 需要更新任务时，再添加一个 Supabase 节点，选择更新操作，用返回的 `id` 筛选记录，将 `status` 改为 `done`。

之后可以按需求将手动触发器换成表单、Webhook 或定时触发器，用来收集客户请求、交付更新等结构化记录。Supabase 凭据保存在 n8n 服务端。

### 用 Metabase 汇总项目费用

打开 Metabase，进入 **Admin settings > Databases > Add a database**，选择 PostgreSQL，填写：

| 字段 | 值 |
| --- | --- |
| Display name | `Home project costs` |
| Host | Supabase 的应用域名，不带协议前缀 |
| Port | `45432`，或 Olares 中显示的会话池映射端口 |
| Database name | `postgres` |
| Username | `postgres.supabase` |
| Password | 解码后的 `POSTGRES_PASSWORD` |
| SSL | 此包的局域网连接使用关闭状态 |

保存连接，针对这个数据库新建 SQL 查询：

```sql
select project, amount
from public.project_costs
order by id;
```

需要计算费用总额时，运行：

```sql
select count(*) as records, sum(amount) as total_usd
from public.project_costs;
```

示例数据会返回 3 条记录，总额为 600 美元。保存查询并将其添加到仪表盘，即可用同样方式跟踪自己的项目费用。事务连接池 `46543` 也支持这些查询。两个连接池都使用 `postgres.supabase`，其中后缀是连接池的租户名。

:::warning 数据库权限和网络范围
这里使用安装实例的数据库管理员账号，适用于由你管理的 Metabase。向他人开放报表前，应配置专用只读数据库账号及相应的 Metabase 权限。TCP 映射允许局域网或 VPN 连接，其访问范围不只限于 Metabase。数据库连接不能使用 API key，也不能填写浏览器的 HTTPS 入口。
:::

### 用 Flowise 查询项目资料

此场景把 Supabase 作为 Flowise 的向量库。Flowise 保留自己的应用数据库配置，不需要为这个流程直接连接 Supabase 的 PostgreSQL 端口。

#### 准备 Flowise 和 Router

在 Router 中设置默认对话模型和默认 embedding 模型。本例分别使用 `default-chat` 和 `default-embedding`。从 Router 的模型连接示例中，复制 **Apps in Olares** 对应的 OpenAI 兼容 **Base URL**，保留 `/v1`。其他调用位置及密钥要求见[连接 AI 应用](https://www.olares.com/docs/zh/manual/best-practices/connect-ai-apps)。

本例的 embedding 模型为 Jina CLIP v2，向量维度为 1024。文档写入和检索应使用同一个 embedding 模型。换成不同维度的模型时，需要使用匹配的向量列并重新建立索引。

:::details 在 Flowise 模型下拉框中加入 Router 默认路由
此版本的 OpenAI 节点通过下拉框选择模型。搭建流程前，先将 Router 默认路由加入本地模型列表。

1. 在 Control Hub 中打开 Flowise 容器的 **Terminal**，运行：

   ```bash
   node <<'NODE'
   const fs = require('fs');
   const base = '/usr/local/lib/node_modules/flowise/node_modules/flowise-components';
   const source = [base + '/models.json', base + '/dist/models.json']
     .find(path => fs.existsSync(path));
   if (!source) throw new Error('Bundled model catalog not found');
   const catalog = JSON.parse(fs.readFileSync(source, 'utf8'));
   for (const [category, provider, name] of [
     ['chat', 'chatOpenAI', 'default-chat'],
     ['embedding', 'openAIEmbeddings', 'default-embedding']
   ]) {
     const entry = catalog[category].find(item => item.name === provider);
     if (!entry) throw new Error('Model provider not found: ' + provider);
     if (!entry.models.some(model => model.name === name)) {
       entry.models.push({ label: name, name });
     }
   }
   fs.writeFileSync('/home/node/.flowise/olares-models.json', JSON.stringify(catalog, null, 2));
   NODE
   ```

2. 在 **ConfigMaps > flowise-config** 的 `data` 下添加以下配置，然后重启 Flowise：

   ```yaml
   MODEL_LIST_CONFIG_JSON: "/home/node/.flowise/olares-models.json"
   ```

这个方法保留内置模型选项，再加入两个默认路由。已经维护自定义模型列表时，请在现有文件中添加路由，不要替换原配置。与下文的兼容设置一样，直接修改 ConfigMap 的内容可能在应用升级时被覆盖。
:::

:::details Flowise 3.1.4 镜像的 WebSocket 兼容处理
此镜像实际报告版本为 3.1.2，使用 Node.js 20。其中的 Supabase 依赖可能报错 `Node.js 20 detected without native WebSocket support`。使用此版本时，先完成以下处理：

1. 在电脑上创建 `supabase-websocket.cjs` 文件，内容为：

   ```js
   globalThis.WebSocket ||= require('/usr/local/lib/node_modules/flowise/node_modules/ws');
   ```

2. 通过 Files 将文件上传到 `Data/flowise/`，它会在 Flowise 容器中挂载为 `/home/node/.flowise/supabase-websocket.cjs`。
3. 在 Control Hub 中打开 Flowise 命名空间，选择 **ConfigMaps > flowise-config**，在 `data` 下添加：

   ```yaml
   NODE_OPTIONS: "--require=/home/node/.flowise/supabase-websocket.cjs"
   ```

   已有 `NODE_OPTIONS` 时，在原值后追加这个参数。
4. 重启 Flowise 工作负载。具体操作见[在 Control Hub 中配置环境变量](https://www.olares.com/docs/zh/manual/olares/settings/manage-app-env)。

直接在 Control Hub 中修改的配置可能在应用升级时被覆盖。保留文件并在需要时重新设置，或使用已包含该兼容修正的应用包。
:::

#### 创建资料存储

在 Supabase 的 **SQL Editor** 中运行：

```sql
create extension if not exists vector with schema extensions;
create table public.project_documents (
  id uuid default gen_random_uuid() primary key,
  content text,
  metadata jsonb default '{}',
  embedding extensions.vector(1024)
);
alter table public.project_documents enable row level security;

create function public.match_project_documents(
  query_embedding extensions.vector,
  match_count integer default 4,
  filter jsonb default '{}'
) returns table(id uuid, content text, metadata jsonb, similarity float)
language sql stable security invoker
set search_path = public, extensions
as $$
  select id, content, metadata,
         1 - (embedding operator(extensions.<=>) query_embedding)
  from public.project_documents
  where metadata @> filter
  order by embedding operator(extensions.<=>) query_embedding
  limit match_count
$$;
```

#### 搭建问答流程

在 Flowise 中新建 chatflow，添加以下节点：

| 节点 | 配置 |
| --- | --- |
| Plain Text | 在 **Text** 中填写项目资料，将 **Additional Metadata** 设为 `{"project":"Lakeview"}` |
| OpenAI Embeddings | **Model Name** 为 `default-embedding`，**Base Path** 使用 Router 地址，**Batch Size** 为 `1`，**Encoding Format** 为 `float` |
| Supabase | **Supabase Project URL** 填 API URL，凭据填 `service_role`，**Table Name** 为 `project_documents`，**Query Name** 为 `match_project_documents` |
| ChatOpenAI | **Model Name** 为 `default-chat`，**Base Path** 使用 Router 地址 |
| Retrieval QA Chain | 接入对话模型和 Supabase 检索器 |

Olares 内的应用调用 Router 不需要 API key。模型凭据字段必须有值时，可以填写占位值 `olares`。

将 Plain Text 的 **Document** 输出和 OpenAI Embeddings 接入 Supabase，再将 **Supabase Retriever** 和 ChatOpenAI 接入 Retrieval QA Chain。保存流程，先执行向量写入操作，再开始提问。

第一份资料可以使用：

```text
Lakeview cabinet delivery is on 10 November 2026.
Confirmation reference: LAKEVIEW-6728.
```

提问“What is the Lakeview cabinet delivery date and confirmation reference?”，将回答与原始资料对照。再添加一个 Plain Text 节点，填写 Riverside 的资料和 `{"project":"Riverside"}` 元数据。只想检索 Riverside 时，将 **Supabase Metadata Filter** 设为这个 JSON 对象。

本例使用的 Jina CLIP v2 服务要求每次只输入一条文本，因此 embedding 批次设为 1。只有在所选服务支持批量输入时，才提高批次大小。

### 在 Code Server 中开发小应用

在 Code Server 中准备一个 Node.js 项目。以下 SDK 示例需要 Node.js 22 或更新版本以及 npm。Code Server 编辑器本身不保证附带 npm。先按 [Node.js 安装说明](https://nodejs.org/en/download)准备项目运行环境。

在 Studio 中运行：

```sql
create table public.user_notes (
  id uuid default gen_random_uuid() primary key,
  owner_id uuid not null,
  note text not null
);
alter table public.user_notes enable row level security;
grant select, insert, update, delete on public.user_notes to authenticated;
create policy own_notes on public.user_notes
for all to authenticated
using (auth.uid() = owner_id)
with check (auth.uid() = owner_id);
```

打开 **Authentication > Users > Add user > Create new user**，填写邮箱和密码。本地示例保留 **Auto confirm user?**，然后创建用户。这样会创建已确认的应用账号，不发送确认邮件。

在 Code Server 的项目终端中安装 SDK：

```bash
npm install @supabase/supabase-js@2.118.0
```

创建 `.env`，填写自己的实例信息及刚创建的用户账号：

```dotenv
SUPABASE_URL=https://YOUR_SUPABASE_API_HOST
SUPABASE_ANON_KEY=YOUR_LEGACY_ANON_KEY
SUPABASE_USER_EMAIL=YOUR_USER_EMAIL
SUPABASE_USER_PASSWORD=YOUR_USER_PASSWORD
```

将 `.env` 加入 `.gitignore`，再创建 `notes.mjs`：

```js
import { createClient } from '@supabase/supabase-js';

const client = createClient(
  process.env.SUPABASE_URL,
  process.env.SUPABASE_ANON_KEY,
  {
    auth: { persistSession: false },
    realtime: { transport: WebSocket }
  }
);

const { data: session, error: loginError } =
  await client.auth.signInWithPassword({
    email: process.env.SUPABASE_USER_EMAIL,
    password: process.env.SUPABASE_USER_PASSWORD
  });
if (loginError) throw loginError;

const { error: insertError } = await client.from('user_notes').insert({
  owner_id: session.user.id,
  note: 'Ask the Lakeview contractor to confirm the delivery window.'
});
if (insertError) throw insertError;

const { data: notes, error: readError } =
  await client.from('user_notes').select('id, note');
if (readError) throw readError;
console.table(notes);

const { data: greeting, error: functionError } =
  await client.functions.invoke('hello', { body: { name: 'Lakeview' } });
if (functionError) throw functionError;
console.log(greeting);
await client.auth.signOut();
```

运行 `node --env-file=.env notes.mjs`，终端会显示当前用户的笔记，以及应用包内置 `hello` Edge Function 的返回内容。根据上面的策略，另一个登录用户不能读取这些笔记。遇到策略错误时，不要通过将 `anon` 换成 `service_role` 来绕过限制。

## 扩展自己的应用

在 Studio 的 **Storage** 中创建私有 bucket，用来保存收据或项目文件。通过 SDK 访问前，为目标用户配置存储策略。上传、下载和短时签名 URL 都使用同一个 API 地址。参考 [Storage 访问控制](https://supabase.com/docs/guides/storage/security/access-control)。

需要实时更新时，将目标表加入 `supabase_realtime` publication，再通过 SDK 订阅。保留 RLS 策略，并在数据库订阅准备好后再依赖首条事件，尤其是刚将表加入订阅时。参考 [Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes)。

用户认证、文件存储、实时更新和函数，让应用可以在共享数据库之外继续扩展。外部登录提供方和邮件发送需要单独配置。本地自动确认用户并不会完成这些配置。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| n8n 或 Flowise 认证失败 | 使用 **Supabase API** 地址和 legacy `service_role` 密钥 |
| Metabase 无法连接 | 检查映射端口、主机是否可达、数据库密码及 `postgres.supabase` 用户名 |
| Metabase 已连接但看不到数据 | 检查所选 schema 和数据库账号权限 |
| Flowise 提示缺少 WebSocket 支持 | 按上文处理对应版本的兼容问题 |
| Flowise embedding 提示只能输入一条文本 | 将 **Batch Size** 设为 `1` |
| SDK 查询没有返回记录 | 先检查登录用户和 RLS 策略，再检查凭据 |

规划备份时，要同时考虑 PostgreSQL 数据和上传的存储对象。能够打开 Studio 或查询到记录，不等于已经备份数据库。
