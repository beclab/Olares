# Goose acceptance results — 2026-10-13

## Conclusion

Acceptance is not complete. The tested conversations and file workflows work, but the normal restart request timed out after stopping the app. The timezone mismatch belongs to the old deployment and is excluded from release failure assessment at the user's request. A subsequent resume restored service without losing files or session history.

This run covers the existing deployment on Olares `1.12.7-20260908`, Goose server/Desktop `1.54.0`, Terminal `0.0.14`, and amd64. The default model was `unsloth/Qwen3.6-27B-MTP-GGUF:UD-Q4_K_XL` through AI Router, with engine concurrency set to 1. Fresh installation from Olares Market could not be exercised because the listing was unavailable. This run does not establish arm64, macOS, or Linux Desktop coverage.

Results distinguish automated tests from human verification. The user explicitly confirmed that Desktop reconnection, rejection/recovery of an incorrect connection secret, and VPN interruption/recovery all passed. No credentials are included in this report.

Summary: 15 passed, 5 partially verified, 1 failed, and 1 blocked. The old-deployment timezone observation is not counted as a release failure.

## Findings requiring follow-up

1. Verify timezone inheritance after deploying the intended release chart. Changing the Olares user's timezone was unnecessary because the existing UTC/Asia/Shanghai mismatch already demonstrated the defect in this deployment.
2. Investigate the Olares restart timeout separately from data persistence. Do not report a successful resume as a successful restart request.
3. CLI model errors can return exit code 0. Automation must inspect the error/result content as well as the process status.

## Final state

Goose was restored to `custom_olares_router` / `default-chat`, with automatic session naming disabled and Home/External access disabled. Its ACP entrance retained `internal` access; the Terminal entrance retained `private` access. Test documents and dedicated marker files were retained for inspection. User timezone and shared model configuration were not changed.

The proposed docs were adjusted to use the v1.54.0 Desktop labels: External Backend (ACP), Use external backend, Backend Base URL, and Remote Working Directory (optional). Full-site build remains blocked by the previously identified missing image in an existing page; that is separate from runtime acceptance.

## Restart reproduction follow-up

After the initial failed restart, three additional attempts were performed sequentially using the same CLI/API restart path. All three reproduced a request timeout and a final stopped state. Attempt 2 was initially stopping when the request timed out, then settled to stopped before recovery. Attempts 2 and 3 returned after approximately 30.36 and 30.34 seconds respectively. Explicit resume succeeded each time.

| Additional attempt | Restart result | Settled state | Recovery |
|:---|:---|:---|:---|
| 1 | Context deadline exceeded | Stopped; no pods | Resume successful |
| 2 | Context deadline exceeded, about 30.36 s | Stopped | Resume successful |
| 3 | Request timeout, about 30.34 s | Stopped | Resume successful |

Reproduction rate for these additional attempts is 3/3. This establishes a repeatable failure in the tested CLI/API path; it does not establish that restarting through the graphical Olares interface fails in the same way. Final health was 200, both example file hashes were unchanged, the manually renamed session was retained, and the existing connection secret still authenticated.
