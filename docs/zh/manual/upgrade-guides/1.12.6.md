# 升级到 Olares 1.12.6

如果从 Olares 1.12.5 或更早版本升级，请使用本指南检查 1.12.6 对现有应用和工作流的影响，并确认是否需要执行额外操作。

:::warning 更改应用前
先打开应用的迁移指南，按要求备份或导出数据。卸载旧应用时，除非指南明确要求，否则不要选择**同时删除本地数据**。该选项可能永久删除模型、工作流、设置或其他应用数据。
:::

## 迁移旧版共享应用

Olares 1.12.6 之前，共享应用由服务端组件和独立的客户端入口组成。新架构只保留一个由管理员集中管理的共享服务。有权限的成员无需再安装独立客户端，可直接从启动台打开带界面的共享应用。

系统升级后，旧版 v2 共享应用仍可启动、停止和使用，但不能直接升级到新架构。打开应用市场中的应用详情页，检查**信息** > **兼容性**：

- 旧版 v2 应用通常显示 `Olares >=1.12.3-0, <1.12.6`。
- 新版共享应用显示 `Olares >=1.12.6-0`。

根据应用选择迁移方式：

- **ComfyUI**：卸载 **ComfyUI Shared** 时不要删除本地数据，然后安装新版 ComfyUI。安装后检查模型、插件、工作流和输入/输出文件是否完整。参见 [ComfyUI 迁移说明](/zh/use-cases/comfyui-common-issues#how-to-migrate-to-the-new-comfyui-after-upgrading-to-olares-1126)。
- **Dify**：将每个应用导出为 DSL 文件，并下载知识库原始文档。日志、对话、处理后的分段和现有向量索引不会保留。参见[迁移 Dify](/zh/use-cases/dify-upgrade)。
- **OnlyOffice**：按迁移指南备份数据，安装兼容 1.12.6 的版本，再恢复数据。参见[迁移 OnlyOffice](/zh/use-cases/onlyoffice-migration)。
- **SearXNG**：从**偏好设置** > **Cookies** 复制偏好设置哈希值，安装新版应用后恢复。参见[迁移 SearXNG](/zh/use-cases/searxng)。
- **Xinference**：重新安装应用并下载所需模型。新版采用公共目录和新的存储结构，现有模型无法自动迁移。参见[迁移 Xinference](/zh/use-cases/xinference)。
- **没有用户数据的应用**：Falco、MTranServer 等应用可直接卸载 v2 版本，再从应用市场安装新版本。

架构说明和完整迁移选项参见[共享应用](/zh/manual/olares/market/shared-apps)。

## 从独立 Ollama 迁移到 Engine Base

从 Olares 1.12.6 起，应用市场不再提供独立 Ollama 应用。已安装的应用仍可运行，也可以继续使用 CLI 和 API 端点，但不会再获得更新。

建议从应用市场安装 **Ollama Engine Base**，并在 Model Console 中创建模型实例。每个实例都有独立的 Base URL、加速器状态和性能数据。

1. 从应用市场安装 **Ollama Engine Base**。
2. 为原来使用的模型创建实例。
3. 等待模型下载完成，确认实例正常运行。
4. 从 Model Console 复制 Base URL。
5. 在 Open WebUI、LobeChat、Agent 或其他客户端中替换旧的 Ollama 端点。
6. 确认新连接可用后，再移除独立 Ollama 应用。

关于引擎选择、模型来源、加速器设置和客户端连接，参见[使用 Engine Base 运行本地大模型](/zh/use-cases/llm-base-apps)。

## 使用新的应用开发流程替代 Studio

Studio 已从应用市场下架。应用打包和移植改用 Olares CLI 和 `olares-chart` Agent Skill。

继续开发 Olares 应用：

1. 安装 Olares CLI 和 Agent Skills，或使用已内置这些工具的 Olares Agent 应用。
2. 使用 Chart 工作流创建、检查和测试应用包。
3. 按最新提交流程验证 Chart，并向 `beclab/apps:main` 创建 Draft PR。

参见[安装与使用 Agent Skills](/zh/developer/cli-agent-skills)和[提交应用](/zh/developer/develop/submit-apps)。

## 查看其他升级注意事项

### AI 应用

Olares 1.12.6 调整了 AI 应用使用资源和加速器的方式。如果升级前安装的 AI 应用无法正常启动，请卸载旧版本，并从应用市场安装最新兼容版本。如果已在 1.12.6 RC 阶段完成该操作，则无需再次处理。

卸载包含用户数据的应用前，先查看迁移指南。除非已有可靠备份，或指南明确说明数据可删除，否则不要删除本地数据。

### Sonarr、Radarr 和其他 *Arr 应用

从 Olares 1.12.6 起，*Arr 应用通过内部入口 URL 通信，不再使用 Provider URL。更新连接设置前，现有集成可能无法正常工作。

1. 将每个 *Arr 应用和下载客户端更新到适用于 Olares 1.12.6 的最新版本。
2. 依次打开**设置** > **应用** > **[应用名称]** > **入口**。
3. 将**认证级别**设为**内部**，然后复制 HTTPS 端点。
4. 在 Prowlarr、Sonarr、Radarr、下载客户端和其他集成中替换旧 URL。
5. 使用应用中的**测试**功能。连接成功后再保存设置。

参见 [*Arr 应用升级说明](/zh/use-cases/arrs-upgrade)。

### Olares One 自动开机

Olares One 现在可以在断电恢复后自动开机。开关位于**设置** > **我的 Olares** > **我的硬件**，但需要受支持的 EC 固件版本。

:::warning 更新固件前
严格按照官方说明操作，确保设备电源稳定，不要中断更新。固件更新中断可能导致设备无法正常启动。
:::

先更新 EC 固件，并在 BIOS 中确认版本，再启用**自动开机**。参见[管理 BIOS 和 EC](/zh/one/update-firmware)。

## 升级后检查系统

1. 手动刷新 Olares 桌面。
2. 打开常用应用，确认可以正常启动。
3. 从各客户端测试共享应用入口和 API 连接。
4. 确认迁移的数据、模型、工作流和设置完整。
5. 新应用及其集成确认可用后，再删除旧版数据。

版本概览参见 [Olares 1.12.6 发布博客](https://www.olares.cn/blog/olares-1-12-6/)。新增和更新的文档参见[文档更新动态](/zh/manual/release-notes)。
