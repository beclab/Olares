# 使用 Colibri 在 Olares 上运行更大的 MoE 模型

Colibri 是一个带有网页聊天界面的本地 AI 推理引擎。它可以加载受支持的 GGUF 模型。对于混合专家模型（MoE），它能按需从磁盘读取专家权重，减少将全部专家常驻内存的需要。

当完整模型权重需要的常驻内存过多时，这种方式可以降低运行门槛。你可以设置系统内存上限和显存额度，显存填 0 时由 CPU 推理。资源较少时，首次响应和生成可能明显变慢，尤其是长输入。

在 Olares 上，你可以复用已有的模型文件，并使用 Olares 登录直接进入聊天界面。本教程使用 Qwen3.6-35B-A3B，将一段会议记录整理为待办事项，再导出对话保存结果。

选择 Qwen3.6-35B-A3B 只是为了方便演示操作流程，Colibri 并不要求使用这一特定模型。你可以换用其他受支持、且符合可用资源条件的 GGUF 格式 MoE 模型。不同模型、量化方式和上下文长度的内存占用及响应速度会有所不同。

## 学习目标

在本教程中，你将学习如何：

- 根据可用资源设置内存和显存额度，并选择已有的 GGUF 模型。
- 使用本地模型整理会议记录，并导出对话。
- 将聊天连接切换到 Olares Router 的默认聊天模型。

## 前提条件

- 一台运行 Olares 1.12.7 或更高版本的 amd64 设备，并支持 AVX2。
- Colibri 0.2.34，并有足够的可用资源加载所选模型。
- 主机需有 NVIDIA 设备。采用 GPU 加速时，需要与 Blackwell sm_120 构建兼容的 NVIDIA GPU，以及支持 CUDA 13.0 的 NVIDIA 驱动。此构建已在 RTX 5090 Laptop GPU 上测试，不适用于旧款 NVIDIA GPU 加速。
- 一份已下载、可由 Colibri 加载的 GGUF 模型文件。本教程使用 Qwen3.6-35B-A3B 的 `UD-IQ4_XS` 量化文件，权重文件约 16.5 GiB。即使采用较小的常驻内存预算，也需要为完整权重保留磁盘空间。

## 准备模型文件

打开 Files，进入 `Common/huggingface`，确认要使用的 GGUF 文件已放在该目录或其子目录中。已有的 Hugging Face 缓存可以直接使用，保留 `snapshots` 目录结构和相对链接即可，无需移动文件或复制路径。

配套的 `mmproj` 视觉投影文件应与主权重保存在同一目录中。Colibri 会把它归到对应模型下作为视觉附件展示，不会将它列成第二个聊天模型。发现视觉文件不代表当前引擎已启用图像输入，具体能力以加载后的状态为准。

Colibri 只读使用原有权重，导入索引和模型选择保存在应用自己的数据目录中。安装包不包含模型权重，也不会自动下载模型。

硬盘需要能容纳完整模型文件。Colibri 按需读取专家权重，内存较小时，硬盘读取速度也可能影响响应，建议将模型放在 SSD 上。增加硬盘容量可以存放更大的模型，但不保证模型能够运行，仍需满足内存、显存和模型兼容性要求。

## 设置内存和显存

安装时只需按可用资源填写内存上限和显存额度，其他设置保持默认。本例填写 `32Gi` 系统内存上限和 `8Gi` 显存额度。这是一组已测试的示例配置，不是所有模型的最低要求。

| 设置 | 本例填写 | 说明 |
|---|---|---|
| `MEMORY_LIMIT` | `32Gi` | Colibri 主容器的系统内存上限，不是显存 |
| `GPU_MEMORY_LIMIT` | `8Gi` | 分配给应用的总显存额度 |

`MEMORY_LIMIT` 和 `GPU_MEMORY_LIMIT` 在安装时必填，没有预设值。正数需带 `Mi` 或 `Gi` 单位，例如 `32Gi`、`48Gi` 或 `49152Mi`，不要填写 `48GB` 或只填 `48`。`1Gi` 等于 `1024Mi`。

应用将内存上限的 75% 换算为引擎预算，并为运行时、上下文和文件缓存留出余量。例如，`32Gi` 上限对应约 25 GB 的十进制引擎预算。内存上限不会提前占满，也不会增加机器的物理内存。额度过低仍可能导致模型加载或生成失败。

显存额度包含模型权重、专家缓存和运行缓冲，不是额外的一份专家缓存。GPU 模式最低接受 `4Gi`，应用从总额度中保留 `2Gi` 给 CUDA 和临时缓冲，其余用于引擎放置模型。实际显存不一定在启动后立即占满。

显存填 `0` 时关闭 CUDA，使用 CPU 推理。填写 `4Gi` 或更大的显存额度时启用 GPU 加速。两种情况使用同一个安装入口，Olares 仍会记录 NVIDIA 设备绑定。

### 安装后调整资源

需要调整内存上限时，在 Olares 设置中打开 Colibri 的环境变量设置，修改 `MEMORY_LIMIT`。保存后应用会重启并重新加载已选择的模型，请先导出需要保存的对话。

`GPU_MEMORY_LIMIT` 在安装后不可直接编辑。需要改变显存额度时，卸载应用时保留应用数据，再安装并填写新的额度。填写 `0` 即可改为 CPU 推理。共享目录中的模型权重无需重新下载。

## 扫描并选择本地模型

1. 从启动台打开 Colibri。尚未加载模型时，会进入“本地模型”页面。
2. 点击**重新扫描**，查看 `Common/huggingface` 中发现的模型。列表展示名称、主权重路径、架构和大小，视觉附件显示在所属模型下。分片 GGUF 会合并为一个选项，缺少分片时不能加载。
3. 选中 **Qwen3.6-35B-A3B**。标为不可选的项目会说明原因，例如当前 Colibri 引擎不支持其架构。
4. 点击**加载所选模型**，检查页面内的确认提示，再点击**确认继续**。
5. 等待状态显示“模型已就绪”，然后点击**进入聊天**。大型模型的加载可能需要几分钟，等待期间可以展开**加载日志**查看进度。

![在 Colibri 中选择本地模型，视觉文件作为对应模型的附件展示](/images/manual/use-cases/colibri-moe-models-en.jpg#bordered)

模型选择会保存到应用数据中，重启应用后会重新加载同一个模型，不会自动改选扫描结果中的第一个文件。保存的文件被删除或移动时，重新扫描并选择其他模型即可。

需要更换模型时，在聊天页面左侧点击本地模型图标，新标签页会打开模型管理页面。先等待当前回复结束并导出需要保存的对话，再选择其他模型。新模型就绪后，通过**进入聊天**开启新对话。

点击**停止本地模型**并确认后，推理进程退出并释放已使用的内存和显存。采用 GPU 模式时，应用仍保留 Olares 的 GPU 分配，后续可以重新选择模型。停止状态也会保存，重启后不会自动恢复加载。

## 使用本地模型整理会议记录

### 连接本地引擎

1. 进入聊天页面后，下文按英文界面标注按钮名称。需要切换语言时，点击左下角的设置图标，在 **Settings** > **General** > **Language** 中选择 **English**。
2. 在 **Settings** > **Connection** 中，确认 **Connection service** 为 **Colibri local engine (default)**。保留自动填写的 **API endpoint**。
3. 点击 **Probe server**。出现 **Engine reachable** 后，即可开始对话。连接失败时，先回到本地模型页面确认加载状态。
4. 打开 **Model** 标签页，选择已加载的本地模型。本例将 **Max output tokens** 设为 `512`，保持 **Reasoning** 关闭，让回复集中在简短的会议纪要上。

`512` 只是本例短纪要的最大输出长度，不是模型固定的输出限制。你可以按任务调整，但输入、历史消息和输出的总量不能超过当前上下文上限。

网页通过 Olares 登录完成认证，无需在 Colibri 中填写 API key。

### 生成会议纪要

1. 点击左侧的 **New chat** 图标，新建对话。
2. 将下面这段虚构的会议记录粘贴到输入框，点击发送箭头。你也可以替换为自己的短文本。

   ```text
   请将以下会议记录整理成一份简洁的会议纪要。
   先列出已确认的决定，再用表格列出任务、负责人和截止日期。
   原文没有提供的信息请写“待确认”，不要补充推测。

   会议记录：
   团队决定在 11 月 10 日发布新版帮助中心。
   张敏负责整理常见问题，11 月 6 日前完成。
   陈宇负责检查页面链接，11 月 8 日前完成。
   产品截图还需要更新，负责人和完成时间尚未确定。
   ```

3. 等待回复逐步显示。对照原文检查待办表，尤其是负责人和截止日期，确认未确定的事项仍标为“待确认”。
4. 在同一对话中继续输入“请把这些待办事项改写成一段发给团队的通知”，将纪要整理成可直接使用的文本。

   ![Colibri 聊天界面，展示本地模型的流式回复](/images/manual/use-cases/colibri-moe-chat-en.jpg#bordered)

   图中使用英文界面演示同一会议任务。

本版本默认提供 16K 上下文，输入、历史消息和输出共同占用这一空间。处理较长记录时，可先按主题分段整理，再用较短的总结继续对话。即使输入未超过上下文上限，较低的内存或显存额度仍可能增加等待时间。

### 导出对话

1. 回复完成后，点击页面右上角的 **Export conversation** 图标。
2. 选择 **Markdown (.md)**，将对话下载到电脑。文件包含输入记录和模型回复，方便之后整理或分享。需要结构化保存时，也可以选择 **JSON (.json)**。

:::warning 保存后再刷新
当前版本的聊天记录和生成参数不会在刷新页面后保留。关闭或刷新页面前，先导出需要保存的对话。
:::

## 资源配置与性能参考

对本例的 Qwen3.6-35B-A3B `UD-IQ4_XS`，`32Gi` 内存上限和 `8Gi` 显存额度可以作为一组已测试的起点。资源允许时，增加内存或显存通常有助于缩短等待。较低额度也可能完成请求，但不代表能保持相同速度。

以下数据来自 Olares One、RTX 5090 Laptop GPU，采用 16K 上下文上限、约 1K 输入和 128 tokens 输出。表中取各档第二次请求，缓存可能已经预热。首 token 时间指开始请求至出现第一个文本片段。

### 不同显存额度

固定 `48Gi` 系统内存上限，比较不同显存额度：

| 显存额度 | 首 token 时间 | 生成速度 |
|---|---:|---:|
| 0，纯 CPU | 8.57 秒 | 20.53 token/s |
| 4Gi | 5.89 秒 | 30.57 token/s |
| 8Gi | 1.87 秒 | 39.81 token/s |
| 12Gi | 0.98 秒 | 46.71 token/s |
| 16Gi | 0.73 秒 | 68.80 token/s |
| 20Gi | 0.25 秒 | 171.13 token/s |

在 `20Gi` 显存额度下，该模型的全部专家权重可放入显存，因此速度提升明显。其他模型不一定在相同额度下达到这一状态。

### 不同内存上限

固定 `8Gi` 显存额度，比较不同系统内存上限：

| 内存上限 | 首 token 时间 | 生成速度 |
|---|---:|---:|
| 48Gi | 1.88 秒 | 42.92 token/s |
| 32Gi | 2.01 秒 | 35.30 token/s |
| 24Gi | 30.98 秒 | 22.80 token/s |
| 16Gi | 33.82 秒 | 20.45 token/s |
| 12Gi | 58.05 秒 | 16.32 token/s |
| 8Gi | 68.61 秒 | 11.18 token/s |

上述内存对比中的两轮请求均已完成，没有因内存不足而终止或发生引擎重启。`32Gi` 和 `48Gi` 两档可让全部专家权重驻留内存，首次响应明显快于更低的内存档位。

显存对比和内存对比分别测试，相同配置的结果会有波动。测试机与 GPU 为共享使用，每档只有两次请求，实际表现还会受到模型、输入内容和其他负载影响。

这里调整的是容器内存上限。测试主机总内存约 94GiB，共享文件缓存可能跨请求和容器保留。这些结果不能等同于在只有 8GiB 或 12GiB 物理内存的设备上运行。

## 可选：切换到 Olares Router

Colibri 也可以使用 Router 提供的模型。开始前，在 Router 中配置一个可调用的聊天模型，并在 **Default models** 页面将其设为默认聊天模型。连接原理可参阅[使用 Olares Router 作为你的 AI 网关](/zh/use-cases/olares-router.md)。

:::info 切换连接不会停止本地引擎
切换连接服务只改变聊天请求的去向，不会停止 Colibri 的后台本地引擎。采用 GPU 模式时，它仍可能占用显存。调用同一张 GPU 上的 Router 模型前，确认显存能同时容纳两项服务。资源不足时，先为 Router 选择不会与 Colibri 争用这张 GPU 的模型服务。
:::

1. 在 Colibri 中，进入 **Settings** > **Connection**。
2. 将 **Connection service** 改为 **Olares Router**，保留自动填写的地址。无需另外创建或填写 API key。
3. 点击 **Probe server**，然后在 **Model** 标签页选择 `default-chat`。
4. 点击 **New chat**，用新的对话发送同一段会议记录。回复由 Router 当前默认的聊天模型生成。之后在 Router 中更换默认模型时，此连接会跟随切换。

Router 的回复不会出现在 Colibri 本地引擎的性能统计中。要回到本地推理，在 **Connection service** 中选择 **Colibri local engine (default)**，重新探测并选择本地模型，再新建对话。
