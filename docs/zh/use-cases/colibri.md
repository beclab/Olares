# 使用 Colibri 在 Olares 上运行更大的 MoE 模型

Colibri 是一个带有网页聊天界面的本地 AI 推理引擎。它可以加载受支持的 GGUF 模型。对于混合专家模型（MoE），它能按需从磁盘读取专家权重，减少将全部专家常驻内存的需要。

当完整模型权重需要的常驻内存过多时，这种方式可以降低运行门槛。代价是磁盘读取和数据传输可能使响应变慢。系统还可能使用额外的可回收文件缓存，因此引擎预算不是整个应用的内存上限。

在 Olares 上，你可以复用已有的模型文件，通过 NVIDIA GPU 运行推理，并使用 Olares 登录直接进入聊天界面。本教程使用低内存 MoE 配置运行 Qwen3.6-35B-A3B，将一段会议记录整理为待办事项，再导出对话保存结果。

选择 Qwen3.6-35B-A3B 只是为了方便演示操作流程，Colibri 并不要求使用这一特定模型。你可以换用其他受支持、且符合可用资源条件的 GGUF 格式 MoE 模型。不同模型、量化方式和上下文长度的内存占用及响应速度会有所不同。

## 学习目标

在本教程中，你将学习如何：

- 切换低内存 MoE 配置，并选择已有的 GGUF 模型。
- 使用本地模型整理会议记录，并导出对话。
- 将聊天连接切换到 Olares Router 的默认聊天模型。

## 前提条件

- 一台运行 Olares 1.12.7 或更高版本的 amd64 设备，并支持 AVX2。
- 与 Blackwell sm_120 构建兼容的 NVIDIA GPU，以及支持 CUDA 13.0 的 NVIDIA 驱动。此预览包已在 RTX 5090 Laptop GPU 上运行，此构建不适用于旧款 NVIDIA GPU。
- 已安装 Colibri，并有足够的可用内存和显存加载所选模型。
- 一份已下载、可由 Colibri 加载的 GGUF 模型文件。本教程使用 Qwen3.6-35B-A3B 的 `UD-IQ4_XS` 量化文件，权重文件约 16.5 GiB。即使采用较小的常驻内存预算，也需要为完整权重保留磁盘空间。

## 准备模型文件

打开 Files，进入 `Common/huggingface`，确认要使用的 GGUF 文件已放在该目录或其子目录中。已有的 Hugging Face 缓存可以直接使用，保留 `snapshots` 目录结构和相对链接即可，无需移动文件或复制路径。

配套的 `mmproj` 视觉投影文件应与主权重保存在同一目录中。Colibri 会把它归到对应模型下作为视觉附件展示，不会将它列成第二个聊天模型。发现视觉文件不代表当前引擎已启用图像输入，具体能力以加载后的状态为准。

Colibri 只读使用原有权重，导入索引和模型选择保存在应用自己的数据目录中。安装包不包含模型权重，也不会自动下载模型。

## 切换低内存 MoE 配置

默认的 `standard` 配置使用应用的通用 RAM 预算。本教程需要切换为 `low-memory-moe`。在 Olares 设置中打开 Colibri 的环境变量设置，将 `INFERENCE_PROFILE` 改为 `low-memory-moe` 并保存。此操作会重启应用，请先导出需要保留的对话。

此配置将引擎 RAM 预算设为 4 GB，专家缓存预算设为 2 GiB，并使用分阶段 GPU 执行。这不是整个应用的资源上限，模型大小、上下文、运行时开销和可回收文件缓存仍会影响实际占用。它面向受支持的 MoE 模型，不是所有 GGUF 文件的通用配置。

需要恢复通用配置时，将 `INFERENCE_PROFILE` 改回 `standard` 即可。

## 扫描并选择本地模型

1. 从启动台打开 Colibri。尚未加载模型时，会进入“本地模型”页面。
2. 点击**重新扫描**，查看 `Common/huggingface` 中发现的模型。列表展示名称、主权重路径、架构和大小，视觉附件显示在所属模型下。分片 GGUF 会合并为一个选项，缺少分片时不能加载。
3. 选中 **Qwen3.6-35B-A3B**。标为不可选的项目会说明原因，例如当前 Colibri 引擎不支持其架构。
4. 点击**加载所选模型**，检查页面内的确认提示，再点击**确认继续**。
5. 等待状态显示“模型已就绪”，然后点击**进入聊天**。大型模型的加载可能需要几分钟，等待期间可以展开**加载日志**查看进度。

![在 Colibri 中选择本地模型，视觉文件作为对应模型的附件展示](/images/manual/use-cases/colibri-moe-models-en.jpg#bordered)

模型选择会保存到应用数据中，重启应用后会重新加载同一个模型，不会自动改选扫描结果中的第一个文件。保存的文件被删除或移动时，重新扫描并选择其他模型即可。

需要更换模型时，在聊天页面左侧点击本地模型图标，新标签页会打开模型管理页面。先等待当前回复结束并导出需要保存的对话，再选择其他模型。新模型就绪后，通过**进入聊天**开启新对话。

点击**停止本地模型**并确认后，推理进程退出并释放其显存。应用仍保留 Olares 的 GPU 分配，后续可以重新选择模型。停止状态也会保存，重启后不会自动恢复加载。

## 使用本地模型整理会议记录

### 连接本地引擎

1. 进入聊天页面后，下文按英文界面标注按钮名称。需要切换语言时，点击左下角的设置图标，在 **Settings** > **General** > **Language** 中选择 **English**。
2. 在 **Settings** > **Connection** 中，确认 **Connection service** 为 **Colibri local engine (default)**。保留自动填写的 **API endpoint**。
3. 点击 **Probe server**。出现 **Engine reachable** 后，即可开始对话。连接失败时，先回到本地模型页面确认加载状态。
4. 打开 **Model** 标签页，选择已加载的本地模型。本例将 **Max output tokens** 设为 `512`，保持 **Reasoning** 关闭，让回复集中在简短的会议纪要上。

网页通过 Olares 登录完成认证，无需在 Colibri 中填写 API key。

### 生成会议纪要

1. 点击左侧的 **New chat** 图标，新建对话。
2. 将下面这段虚构的会议记录粘贴到输入框，点击发送箭头。你也可以替换为自己的短文本。

   ```text
   请将以下会议记录整理成一份简洁的会议纪要。
   先列出已确认的决定，再用表格列出任务、负责人和截止日期。
   原文没有提供的信息请写“待确认”，不要补充推测。

   会议记录：
   团队决定在 11 月 10 日发布新版帮助中心。
   张敏负责整理常见问题，11 月 6 日前完成。
   陈宇负责检查页面链接，11 月 8 日前完成。
   产品截图还需要更新，负责人和完成时间尚未确定。
   ```

3. 等待回复逐步显示。对照原文检查待办表，尤其是负责人和截止日期，确认未确定的事项仍标为“待确认”。
4. 在同一对话中继续输入“请把这些待办事项改写成一段发给团队的通知”，将纪要整理成可直接使用的文本。

   ![Colibri 聊天界面，展示本地模型的流式回复](/images/manual/use-cases/colibri-moe-chat-en.jpg#bordered)

   图中使用英文界面演示同一会议任务。

本预览包的本地上下文长度为 4096 token，输入、历史消息和输出共同占用这个空间。处理较长记录时，先按主题分段整理，再用较短的总结继续对话。不要一次粘贴整份长文档。

### 导出对话

1. 回复完成后，点击页面右上角的 **Export conversation** 图标。
2. 选择 **Markdown (.md)**，将对话下载到电脑。文件包含输入记录和模型回复，方便之后整理或分享。需要结构化保存时，也可以选择 **JSON (.json)**。

:::warning 保存后再刷新
当前版本的聊天记录和生成参数不会在刷新页面后保留。关闭或刷新页面前，先导出需要保存的对话。
:::

## 可选：切换到 Olares Router

Colibri 也可以使用 Router 提供的模型。开始前，在 Router 中配置一个可调用的聊天模型，并在 **Default models** 页面将其设为默认聊天模型。连接原理可参阅[使用 Olares Router 作为你的 AI 网关](/zh/use-cases/olares-router.md)。

:::info GPU 资源仍由本地引擎占用
切换连接服务只改变聊天请求的去向，不会停止 Colibri 的后台本地引擎或释放 GPU。调用同一张 GPU 上的 Router 模型前，确认显存能同时容纳两项服务。资源不足时，先为 Router 选择不会与 Colibri 争用这张 GPU 的模型服务。
:::

1. 在 Colibri 中，进入 **Settings** > **Connection**。
2. 将 **Connection service** 改为 **Olares Router**，保留自动填写的地址。无需另外创建或填写 API key。
3. 点击 **Probe server**，然后在 **Model** 标签页选择 `default-chat`。
4. 点击 **New chat**，用新的对话发送同一段会议记录。回复由 Router 当前默认的聊天模型生成。之后在 Router 中更换默认模型时，此连接会跟随切换。

Router 的回复不会出现在 Colibri 本地引擎的性能统计中。要回到本地推理，在 **Connection service** 中选择 **Colibri local engine (default)**，重新探测并选择本地模型，再新建对话。
